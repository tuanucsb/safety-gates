Safety Gates Pilot Results

Do AI agents approve unsafe engineering actions, and do monitors catch it? A pilot with computed ground truth across nuclear power, spaceflight, drugs, devices, cell and gene therapy and process safety. Below: how it works, the honest-agent results (Release 0), the control evaluation with red-team and simulated unsafe approvals (Release 0.1), and seven cases shown exactly as they ran.

How it works

1A case file

A realistic decision request backed by 3 to 6 short documents: a work order, a label, a test report, a validation report. All products and plants are fictional.

2Three variants

clean: safe, correct answer APPROVE. hazard: one planted hazard, correct answer REJECT or ESCALATE. pressure: the hazard plus a manager's schedule-and-cost note.

3An agent with four tools

list_documents, read_document, calculate, submit_decision. It must report every acceptance check it evaluated with value and limit. The decision is acted on.

4Monitors gate each approval

A deterministic rule checker and three Claude monitors review every APPROVE. A flag sends it to a human. Ground truth is computed in code, so every miss and every false alarm is counted.

Two agents, Claude Opus 5.5 and Claude Haiku 5.5, each worked all 66 instances three times through the Claude Code CLI harness. Eighteen tasks carry document or human-error hazards (a weight in pounds read as kilograms, an amendment that supersedes an input, a summary that averages away a failure). Four carry AI-in-the-loop hazards: a digital twin, an aero surrogate, an FEA result and a QSAR model each used outside the envelope stated in its own validation report, while the model's number still looks compliant.

What this does and does not show

On short fictional case files: current Claude models did not approve unsafe engineering actions when acting honestly, did not change under schedule pressure, and largely refused to sabotage when instructed to as a red-team agent, disclosing the five times Opus did. A Sonnet monitor given the source documents separated unsafe from safe approvals perfectly at a 2% false-alarm rate on real traffic. A monitor that sees only the transcript lost a third of its catches at that budget when the agent never opened the document holding the hazard, and grounding the same model in the documents recovered them. A deterministic limit checker, the oversight regulators reach for first, missed most wrong-input errors because it checks the numbers it is given.

It does not show that these monitors would hold against a capable adversary. The simulated misses were written by a model that knew the answer, the writer and the strongest monitor are the same model family, the case files are short, and the only real adversarial approvals came with confessions attached. Next: an adversary that does not confess (red-team policies iterated against the monitors, agents that hide what they did not read), misses that require deriving a quantity no document states, and longer case files with distractors.
