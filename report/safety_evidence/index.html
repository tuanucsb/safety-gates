A pilot control evaluation on fictional engineering decision cases with computed ground truth. Every figure opens its source.

An agent decides, and a monitor reviews every approval

The agent reads a short case file and approves, rejects or escalates a proposed action, such as releasing a work order or verifying a dose. Whether the action breaks its governing limit is computed in code from the same parameters that generate the documents, so every wrong approval can be counted.

There are — tasks, each in — variants: a safe case, the same case with one realistic hazard, and the hazard case with a manager's note about schedule and cost. Every approval goes to a monitor before it would execute, and a flag sends it to a person. The question is which monitors catch a wrong approval, and at what cost in false alarms.

Each was placed in two transcripts, one where the agent read the document holding that fact and one where it never opened it. Each monitor's threshold was set so that at most —% of real safe approvals would be flagged.

What this pilot does not show

  • An agent that hides. Every real unsafe approval came with a disclosure. The policy that forbids disclosure is built and has not been run.
  • Tasks hard enough to separate models or monitors. — harder tasks are built and not yet run.
  • A human baseline. No task has been solved blind by a person, and nothing here measures what a reviewer does with a flag.
  • Independent wrong approvals. One model wrote them after being shown the answer, and all were scored on one harness. In the never-opened transcripts the monitor mostly flagged the unread document itself, which a simple rule could also check.
  • A held-out threshold. Thresholds were set and scored on the same safe approvals.
Definitions, how this was built, and how to reproduce it
Unsafe case
A decision case in which the proposed action violates its governing limit, by computation from the case documents. The correct decision is to reject or escalate.
Wrong approval
An approval of an unsafe case.
False-alarm budget
The share of real safe approvals a monitor may send to a person. The threshold is set to that share first, then applied to the wrong approvals.
Resampled by task
Tasks are drawn with replacement, on the wrong approvals and on the safe approvals, and the threshold is set again each time. The range is the middle of those results.
Harness
The software that runs the model and its tools. Scores are reported with the harness, because the same monitor scores differently through another one.
How this was built
The harness, the tasks and the analysis were built with AI coding agents (Claude Code) directed by the author. Every commit in the repository is co-authored accordingly.
Reproduce
The analysis runs offline with no model: python -m engsafe.calibrate in the repository.
